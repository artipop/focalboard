# Открытые вопросы по ACP-интеграции

Наблюдения из живых прогонов, которые пока не разобраны. Протокольные факты,
уже выясненные замерами, живут в `../../cmd/acpspike/NOTES.md`.

## 1. `Skill` отклоняется, хотя он в autoAllowTools

В консоли пришёл запрос разрешения с заголовком

> Skill: Reference for the Claude API / Anthropic SDK — model ids, pricing,
> params, streaming, tool use, MCP, agents, caching, token counting, model
> migration. TRIGGER — read BEFORE opening the target file; …

и решением **REJECT**.

Заголовок формируется как `<tool_name>: <description>` (`answerPermission` в
`claudebridge`), то есть `tool_name` здесь — ровно `Skill`, а всё остальное —
описание скилла. Значит совпасть со списком он был должен.

Что проверить:

- в каком порядке шли события: `Skill` добавлен в `autoAllowTools` и в живой
  `config.json` уже после этого прогона, а `LoadConfig` читает файл только на
  старте — возможно, приложение просто работало со старым списком;
- если воспроизведётся на свежем конфиге — смотреть трассу
  (`debugLog: true`, `~/Library/Application Support/Focalboard/acp/acp-debug.jsonl`):
  запись `cli→app control_request` покажет настоящий `tool_name`, а
  `app→ui acp:permission` — с каким `decision` мы его закрыли. Если `tool_name`
  окажется не `Skill` (например, с префиксом), сопоставление в
  `permissionToolName` нужно чинить, а не список.

## 2. Вторую пачку вопросов модель готовит очень долго

После ответа на первый `AskUserQuestion` агент сказал «ещё четыре развилки», и
следующий вызов висел в `PENDING` заметно дольше первого, после чего часть
ответов была выдумана.

Что проверить по трассе:

- есть ли `app→ui acp:question` для второго вызова вообще — если нет, пикер
  нечем было отрисовать, и это баг у нас;
- если есть, но нет `ui→app AnswerQuestion`, дальше должен быть
  `app question_timeout`: сработал `permissionTimeoutMinutes` (по умолчанию 5),
  и модель по инструкции продолжила с допущениями. Тогда это вопрос таймаута,
  а не потерянного сообщения;
- сколько времени прошло между `app→cli` с ответами на первую пачку и
  `cli→app` со вторым `control_request` — это чистое время модели, и на него мы
  повлиять не можем, кроме как показывать, что она думает.

Учесть при чтении трассы: поток текста сбрасывается в UI по таймеру ~60 мс, так
что последний чанк ответа появляется в файле чуть позже соседних событий.
