# Что осталось в дереве зависимостей webapp

Тулчейн (Node 24 / npm 11 / `npm ci` / Vite) и переезд на React 19 + `@dnd-kit` сделаны;
отчёты о том, как это шло, удалены — состояние видно в `package.json` и в CLAUDE.md. Здесь
остаётся только то, что **не сделано**, и способ проверки.

Сейчас на чистой установке: 0 ERESOLVE, 0 уязвимостей, 2 deprecated.

## TODO

- **9 тестов помечены `test.skip`** с `eslint-disable` и причиной (правило `no-only-tests`
  запрещает skip намеренно, поэтому disable точечный и греппаемый — искать `TODO(react-19)`).
  Четыре из них шлют HTML5-события `fireEvent.dragStart/drop`, на которые dnd-kit принципиально
  не реагирует. Переписать их «как было» нельзя: dnd-kit считает коллизии по
  `getBoundingClientRect`, а **у jsdom нет движка раскладки** и он возвращает нули. Варианты —
  подделать геометрию (как `reactFlowEnvironment.ts` делает для React Flow), свести к юнит-тестам
  обработчиков (покрытие ровно то же: они и раньше проверяли не жест, а что позвался `mutator`)
  или отдать в E2E с настоящим браузером.
- **a11y-атрибуты dnd-kit не покрыты.** `role`, `tabindex`, `aria-roledescription`,
  `aria-describedby` — то, чем клавиатура вообще добирается до карточки, и один из главных
  доводов за уход с HTML5 DnD. В снапшотах они спрятаны (`dndKitSnapshotSerializer.ts`),
  потому что dnd-kit вешает их своим планировщиком, а не React-эффектом: замерено — 4/3/3
  падения на трёх одинаковых прогонах. Отдельный тест тоже не помог: в одном прогоне
  атрибутов нет ни одного, в другом весь набор. Нужен browser mode.
- **Ручная мемоизация, которую компилятор не может сохранить.** React Compiler включён, но
  пропускает компоненты, где ручные `useMemo`/`useCallback` не сходятся с выведенными
  зависимостями: сейчас это 4 предупреждения `react-hooks/preserve-manual-memoization` в
  `npm run check`. Рядом 29 предупреждений `react-hooks/set-state-in-effect` — эффекты, которые
  дёргают `setState` синхронно. Ни то, ни другое не ломает сборку, но это и есть остаток чистки.
- **`user-event` 13 → 14**: 468 вызовов должны стать `await`, а объемлющие тесты — `async`.
  Механическая, но широкая правка; ей место в своём коммите.
- **`emoji-mart` → `emoji-picker-element`.** 5.6.0 последний раз публиковался 2024-04-25.
  Замена — тоже веб-компонент, то есть переживёт переезд на Solid, но живой.
- **jest → vitest** (или хотя бы jsdom → happy-dom). Vitest понимает ESM нативно — исчезает весь
  список `transformIgnorePatterns`; у него свой esbuild — исчезает `@swc/jest`; его browser mode
  гоняет тесты в настоящем Playwright-браузере с настоящей раскладкой, то есть тесты dnd-kit
  становятся писабельными. `happy-dom` — вариант поменьше: везёт `ResizeObserver`/`PointerEvent`
  из коробки и убрал бы `whatwg-encoding`, но движка раскладки нет и у него.
- **`react-router-dom@5`** не поддерживается, но peer `>=15` и React 19 не блокирует — отдельным PR.
- **`moment` → `date-fns`**: `date-fns` уже в дереве как зависимость `react-day-picker@10`,
  так что замена в 3 файлах теперь бесплатна.
- **`tsc --noEmit` в `npm run check`.** Типы сейчас не проверяет никто: сборка идёт esbuild-ом,
  тесты — `@swc/jest`, оба просто срезают типы. Именно поэтому ошибки и копились (было 414,
  разобраны до нуля).
- **TypeScript выше 5.9 нельзя**: `@typescript-eslint@8` объявляет peer `>=4.8.4 <6.1.0`.
- Старые селекторы `.emoji-mart-*` в `emojiPicker.scss` и `main.scss` мертвы: v5 рендерит
  в shadow root.

## Проверка

После **каждого** PR-а, на дереве, поставленном через `npm ci`:

- `npm ci` на пустом `node_modules` — записать число строк `npm warn deprecated`, `npm audit`
  (по severity) и наличие ERESOLVE; это и есть метрика прогресса;
- `npm ls` — без `invalid`/`extraneous`;
- `npm run check`, `npm run test`, `npm run pack`;
- `make mac-dmg-wails` — embed-сборка десктопа (webapp попадает в бинарь через `desktop/pack`);
- `npm ci` не должен менять `package-lock.json` ни на байт (проверять `git diff --exit-code`).
