# Почему десктоп открывает localhost-порт, и как его убрать

> Разбор от 2026-08-01, **не сделано**. Записано, чтобы не выяснять заново.

## Что происходит сейчас

`desktop/main.go:46` берёт случайный свободный порт (`getFreePort()`), поднимает на нём
Focalboard-сервер **внутри того же процесса**, а `desktop/proxy.go:67` строит
`httputil.NewSingleHostReverseProxy` на `http://localhost:<порт>` и отдаёт его в
`assetserver.Options.Handler`.

То есть каждый HTTP-запрос из вебвью идёт: custom scheme → наш handler → **TCP на localhost**
→ сервер, который живёт в этом же процессе.

Плюс bootstrap-скрипт (`proxy.go:34`) подставляет в страницу
`window.webSocketBaseURL = http://localhost:<порт>`, чтобы WebSocket шёл мимо custom scheme.

## Порт делает две работы, и первая лишняя

**1. Цель реверс-прокси для HTTP — убирается сегодня.** `assetserver.Options.Handler` принимает
любой `http.Handler`. Можно отдать хендлер самого сервера напрямую и выкинуть сетевой хоп
целиком: инжект bootstrap делается обёрткой над этим хендлером вместо `ModifyResponse`.
Полдня работы, проверяется существующей десктопной сборкой, обратимо.

**2. WebSocket — настоящая причина.** Обработчик кастомной схемы в WKWebView это
`WKURLSchemeHandler`: API вида «запрос → данные ответа», в котором нет понятия постоянного
двунаправленного соединения. Апгрейд до WebSocket через `wails://` не выразим — **и это
ограничение WebKit, а не Wails**, то есть ни одна версия Wails его не снимет. В документации
v3 «no open ports» относится к ассетам, про WS там ничего.

## Шов в коде уже есть

`webapp/src/wsclient.ts` **уже двухтранспортный**:

```ts
ws: WebSocket|null = null              // standalone
client: MMWebSocketClient|null = null  // режим плагина Mattermost
```

`sendCommand` (строка 190) ветвится по `this.client !== null`, транспорт внедряется через
`initPlugin(...)`, а сам интерфейс — шесть методов:

```ts
conn, sendMessage, addFirstConnectListener,
addReconnectListener, addErrorListener, addCloseListener
```

Третий транспорт поверх шины событий Wails вставляется в существующую точку расширения.
Паттерн в проекте уже работает: ACP-консоль стримит события агента через
`window.runtime.EventsOn`, никакого WebSocket там нет.

## План, если возвращаться

1. **Выкинуть прокси** (полдня). `AssetServer.Handler` = хендлер сервера напрямую. Порт остаётся
   только ради WS, но исчезает TCP-хоп на каждый запрос и весь `httputil`.
2. **Транспорт на событиях Wails** (день-два). Реализация `MMWebSocketClient` поверх
   `EventsOn` + bound-метода, на Go-стороне адаптер к `server/ws`. После этого `getFreePort()`
   и `webSocketBaseURL` удаляются.

Что это даёт помимо чистоты:

- **Безопасность**: сейчас сервер слушает localhost, то есть любой процесс на машине может
  в него постучаться. После — не слушает вообще.
- **Открывается `frontend:dev:serverUrl`**: закреплённый порт больше не нужен, потому что
  порта нет. А значит становится доступен HMR в десктопном окне — и заодно уходит паника
  `(*Window).ExecJS` на nil-окне, которая живёт в пути `-reloaddirs` (баг Wails v2.13.0,
  `window.go:189`, проверки на nil там нет).

## Чего делать не надо

Собирать мини-репро на Wails v3 ради этого вопроса: он ответит «нет» на то, что следует из
формы API WebKit. Переезд на v3 — отдельное решение с отдельными основаниями (там alpha,
другой API, сборка через Taskfile, другие биндинги), и на эту задачу он не влияет.
